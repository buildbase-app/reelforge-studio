# Manifest v0.2

A project is one JSON manifest. It is the only thing an agent writes: the server
validates it, stores every change as a new version and renders it. The full JSON
Schema comes from your server: `get_project_schema` (MCP),
`GET /v1/schema/project` (REST) or the resource `reelforge://schema/project`.
Files in the older v0.1 format are migrated automatically.

## A minimal manifest

```json
{
  "schemaVersion": "0.2",
  "projectId": "my-reel",
  "title": "My reel",
  "theme": "midnight",
  "output": { "width": 1080, "height": 1920, "fps": 30, "format": "mp4" },
  "scenes": [
    { "id": "hook", "engine": "remotion", "template": "kinetic-title", "durationSeconds": 3,
      "props": { "headline": "Make reels with agents", "subline": "Self-hosted" } },
    { "id": "steps", "engine": "motion-canvas", "template": "animated-explainer", "durationSeconds": 5,
      "props": { "title": "How it works", "points": ["Plan", "Render", "Post"] } },
    { "id": "card", "engine": "html", "html": "<h1 class='t'>Your own HTML</h1>",
      "css": ".t{color:var(--rf-accent);font-size:120px;margin:40% 8%;animation:in .6s both}@keyframes in{from{opacity:0}}",
      "durationSeconds": 2 }
  ]
}
```

## Top-level fields

| Field | Required | What it is |
| --- | --- | --- |
| `schemaVersion` | yes | `"0.2"` |
| `projectId` | yes | Lowercase letters, digits and dashes, up to 63 characters |
| `title` | yes | 1 to 120 characters |
| `output` | yes | `width` and `height` (even numbers, 16 to 4096), `fps` (24, 25, 30 or 60), `format` (`mp4`, `mov`, `webm`, `gif`, `png-sequence`, `m4a` or `wav`), optional `codec` and `alpha` ([Output formats](/docs/manifest/formats#output-formats)). Any aspect ratio: 1080x1920 (9:16), 1920x1080 (16:9), 1080x1080 (1:1), 1080x1350 (4:5), 3840x2160 (4K); templates reflow for it ([Formats and layouts](/docs/manifest/formats)) |
| `variants` | no | Extra output formats: 1 to 8 of `{ "id", "width", "height", "platform"?, "format"?, "codec"?, "alpha"? }` (even sizes, 16 to 4096). `render_project` then renders one video per variant ([Output variants](#output-variants)) |
| `scenes` | yes | 1 to 50 scenes, played back to back |
| `brief` | no | `title`, `goal`, `audience`, `style`, `language` (BCP 47), `targetSeconds`, `platform` |
| `theme` | no | A theme id (`default`, `midnight` or one made with `create_theme`), or `{ "base": "default", "tokens": { ... } }` for inline overrides. Default `default` |
| `audio` | no | `voice`, `music` and `sfx` (below) |
| `assets` | no | Files the project uses, with licence metadata |
| `captions` | no | `mode` (`off` default or the server's `captions.defaultMode`, `burned`, `sidecar`, `both`), `cues` (`{start, end, text, words?, kind?}` in seconds; `kind: "description"` for audio description), `language` (BCP 47), `tracks` (more languages: `{ "<tag>": { cues } }`), `burnLanguage`, `approval` (set by `update_captions`), `style`, `highlight`, `maxLineChars`, `maxCharsPerCue`. Without cues, captions are built from the voice's word timestamps (TTS or `transcribe_captions`) or scene caption text. One language is burned with libass; every language is written as SRT, WebVTT and ASS next to the MP4, descriptions as a WebVTT `kind=descriptions` track; quality rules are validation warnings |
| `render` | no | `backend`, default `local` |

A whole project is at most 180 seconds.

## Output variants

One project can render several formats in one call. The scenes are laid out
again for each size (the templates reflow; nothing is cropped), at the frame
rate of `output`, and in its format unless a variant sets its own `format`,
`codec` or `alpha` ([Output formats](/docs/manifest/formats#output-formats)):

```json
"output": { "width": 1080, "height": 1920, "fps": 30, "format": "mp4" },
"variants": [
  { "id": "vertical", "width": 1080, "height": 1920, "platform": "tiktok" },
  { "id": "wide", "width": 1920, "height": 1080, "platform": "youtube" },
  { "id": "square", "width": 1080, "height": 1080 }
]
```

`render_project` (`POST /v1/projects/:id/renders`) then starts one render per
variant, each its own job and render id, and answers
`{ "job": ..., "jobs": [...], "batchId": "bat-..." }` (`job` is the first one,
so clients that read only `job` keep working). Each job's params carry its
`variant` and the `batchId`. Pass `"variant": "wide"` to render only one;
an unknown id is `404 not_found` with the list. A variant's `platform` replaces
`brief.platform` for that render (the app-overlay safe area on tall frames).
Every variant is checked against the server's render limits before anything is
queued, and if the queue refuses one of them (quota or queue limits) the jobs
already started for the batch are cancelled. Each variant counts as one render
against a key's quota. Without `variants`, a render is one video at `output`,
as before.

## Scenes

| Field | What it is |
| --- | --- |
| `id` | Unique in the project |
| `engine` | `remotion`, `motion-canvas`, `html` or `hyperframes`; only engines that can render on your server (see `get_capabilities`) |
| `template` | A template of that engine ([Built-in templates](/docs/manifest/templates)) |
| `html`, `css` | For `html` and `hyperframes` instead of a template: your own markup, up to 256 KB together |
| `durationSeconds` or `durationFrames` | Exactly one of them. Seconds are rounded to whole frames |
| `props` | The template's props, checked against its JSON Schema |
| `assets` | Ids of assets the scene uses |
| `transitionIn` | Only `{ "type": "cut" }` exists in v0.2 |
| `notes` | Free text for people; ignored by renderers |

Each template has a duration range; a scene outside it is an error. Scenes with
your own HTML can last 0.5 to 60 seconds and run with no network: inline images
and fonts as `data:` URLs. Theme tokens are CSS variables there: `--rf-bg`,
`--rf-text`, `--rf-muted`, `--rf-accent`, `--rf-accent2`, `--rf-font`,
`--rf-unit` (1% of the shorter side) and the safe-area insets
`--rf-safe-top/right/bottom/left` ([Formats and layouts](/docs/manifest/formats)).

## Audio

```json
"audio": {
  "music": { "asset": "music", "volume": 0.6, "fadeOutSeconds": 1 },
  "voice": { "asset": "voice", "startFrame": 15 },
  "sfx": [{ "asset": "whoosh", "atFrame": 90 }]
}
```

Every referenced id must be an `audio` asset of the project. A voice track can
instead name a `provider` and `text` for `generate_voice` to create the asset.
`music.ducking` is stored but not applied yet (validation warns).

## Assets

```json
"assets": [{
  "id": "music",
  "uri": "asset://ast-0123456789abcdef",
  "mediaType": "audio",
  "license": { "name": "CC0-1.0", "redistributable": true }
}]
```

`uri` is `asset://ast-<16 hex>` (the server's asset store, from
`upload_asset` or `add_asset_from_url`), `project://<relative path>`, or an
`https://` URL that must be imported with `add_asset_from_url` before rendering:
the renderer never downloads during a render. `mediaType` is `audio`, `image`,
`video` or `font`. A missing `license` is allowed but produces a warning.

## Validation

`validate_project` (or `POST /v1/projects/:id/validate`) returns `ok`, every
error with its path (for example `scenes.1.props.headline`) and warnings.
`create_project` and the edit tools refuse an invalid manifest with
`invalid_manifest` and the same list, all problems at once.
